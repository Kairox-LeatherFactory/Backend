## 1. How to run this suite

The committed `.env` **cannot boot the test suite**. `ENVIRONMENT=local` +
`DEBUG=false` + the shipped `SECRET_KEY=dev-only…` trips the guard at
`app/core/config.py:261-267`, and collection dies in `conftest.py:37` before a
single test is selected. See **F150**.

```bash
ENVIRONMENT=local DEBUG=true pytest tests/ -q      # the whole suite
ENVIRONMENT=local DEBUG=true pytest tests/unit -q  # one layer
ENVIRONMENT=local DEBUG=true pytest -m money -q    # the money paths
```

Do **not** export a real `SECRET_KEY` to work around this:
`tests/unit/test_core_blockers.py:80-88` constructs `Settings(environment="production")`
and asserts it refuses the shipped default. A real key in the environment makes that
test pass for the wrong reason — it was the one spurious failure in the first
baseline attempt.

### BLOCKER

**[F147] [SEV: BLOCKER] [production] [app/modules/production/service.py:376, 435, 438]**

**Symptom:** 4 failing tests in `tests/system/test_production_tenancy.py`.
A `CLIENT` login scoped to ACME reads RIVAL's data on three endpoints:

```
cross-tenant leak: ACME's token returned RIVAL's SKUs —
  ['ACME-PO-ACMESTYLE-BLK-M', 'RIVAL-PO-RIVALSTYLE-BLK-M']
cross-tenant leak: ACME read RIVAL's stage progress (HTTP 200)
cross-tenant leak: ACME enumerated RIVAL's pieces (HTTP 200)
```

**Real bug or test bug:** **Real.** The controls in the same file pass — staff still
read across clients (correct), and an unknown id still 404s (correct). Only the
tenancy predicate is missing.

**Why it's wrong:** `client_scope` (`production/router.py:37-41`) computes the
caller's tenant and the router threads it into all three service calls (`:71`, `:98`,
`:110`). The three service methods **accept the kwarg and never read it**:

- `list_pieces_for_sku` (`service.py:376-378`) — signature takes `client_scope`; body
  never mentions it
- `style_progress` (`service.py:435-436`) — `return await self.repo.stage_totals_for_style(style_id)`
- `list_sku_options` (`service.py:438-439`) — forwards `order_id`/`style_id` only

Analytics does the identical thing correctly: `order_tree` adds
`.where(ClientOrder.client_id == client_scope)` (`analytics/service.py:169-170`), which
is what closed **F33**. Production got the parameter but not the predicate.

This is the residue of **F140**. F140 was reported as "the router passes a kwarg the
service does not accept → TypeError". The fix added the parameter, which silenced the
TypeError and left the filter unimplemented — so the endpoints went from *failing
loudly* to *leaking silently*. That is strictly worse, and it is why the three
`test_the_client_scope_gets_are_broken` tests now fail (see F149).

Note these three endpoints also carry **no `require_roles`** — only `client_scope`,
which is a tenancy filter, not an authorization check. So every authenticated role
reaches them, including `VIEWER`.

**Deadline impact:** **July 28 (Phase 1) — already passed.** This is a live
cross-tenant disclosure on shipped Phase-1 endpoints. Per-piece traceability is the
product's headline feature and `/skus/{id}/pieces` is its read surface.

**Fix location (NOT applied):**
- `service.py:376` — thread `client_scope` into `_resolve_sku_id`/`get_sku`, 404 when
  the SKU's `Style.client_order_id → ClientOrder.client_id` ≠ scope
- `service.py:435` — same predicate on the style lookup before `stage_totals_for_style`
- `service.py:438` — pass `client_scope` through to `clients.list_sku_options` and
  filter there
- mirror `analytics/service.py:167-173` exactly; it is already correct and tested

**[F148] [SEV: HIGH] [wage] [app/modules/wages/service.py:410 + app/modules/employees/models.py:34-36]**

**Symptom:** `tests/integration/test_wages_exclusions_and_recompute.py::test_an_out_of_vocabulary_wage_type_crashes_payroll_instead_of_excluding`

```
LookupError: 'daily' is not among the defined enum values.
Enum name: wage_type. Possible values: MONTHLY, PIECE_RATE
```

raised while hydrating `Employee` inside `employees.list_all` — i.e. **before any wage
arithmetic runs**.

**Real bug or test bug:** **Real**, though the test asserts the current behaviour and
therefore passes. The defect is that a documented safety net is dead code and the real
failure mode is unhandled.

**Why it's wrong:** `_as_wage_type` (`service.py:65-81`) exists specifically to coerce a
bad `wage_type` to `None` so the worker fails both branch tests and is **named** on the
run under `excluded_untyped_employees` (`:416-419`, `:518-522`). Its docstring
(`:66-73`) justifies this by saying raw strings "have leaked through before".

But `Employee.wage_type` is `Mapped[WageType]` over `Enum(WageType)`
(`employees/models.py:34-36`) — non-nullable, with SQLAlchemy's value lookup on **read**.
A legacy or hand-updated row holding `'daily'` raises `LookupError` during hydration at
`service.py:410`, before `_as_wage_type` is ever called. Consequences:

1. `excluded_untyped_employees` is **unreachable** — the branch at `:417-419` cannot
   fire, and the reporting channel it feeds is dead.
2. The actual failure is an unhandled 500 that kills the **entire run**, so every other
   employee's pay is blocked too — the opposite of the "exclude one, report them"
   design.

The positive control (`test_the_untyped_exclusion_channel_reports_nobody_on_a_clean_roster`)
confirms the channel is well-formed, just unreachable.

**Deadline impact:** July 28 (Phase 1). Latent — needs a non-conforming row to fire —
but when it fires it blocks all payroll with an opaque error, at the worst possible
moment.

**Fix location (NOT applied):** `wages/repository.py` / `employees/repository.py:list_all`
— read `wage_type` as a plain string (`Employee.__table__.c.wage_type`) and let
`_as_wage_type` do the coercion it was written for; or add a values_callable/validation
layer. One line to make the safety net reachable.

**[F150] [SEV: MED] [core] [app/core/config.py:261-267 + .env:2-3,17]**

**Symptom:** `pytest tests/` on a clean checkout:

```
RuntimeError: SECRET_KEY is still a well-known placeholder while
ENVIRONMENT='local' DEBUG=False. Set a real SECRET_KEY.
```

raised from `conftest.py:37` — **collection fails, zero tests run.**

**Real bug or test bug:** **Real**, in the environment contract rather than in logic.

**Why it's wrong:** the guard is correct and deliberate (F32/H5): the dev default
survives only when `environment == "local"` **AND** `debug` is on (`config.py:256`). The
committed `.env` ships `ENVIRONMENT=local` with `DEBUG=false` and the placeholder key —
i.e. the repo's own default configuration is exactly the combination the guard rejects.
The suite is therefore unrunnable as checked out, and the obvious workaround (export a
real `SECRET_KEY`) silently breaks `test_core_blockers.py:80-88`, which asserts the
guard fires for `environment="production"`.

**Deadline impact:** July 28. Not a runtime defect, but it blocks CI and every new
developer's first run — and the natural workaround produces a green suite that is
lying about F32.

**Fix location (NOT applied):** `.env:3` → `DEBUG=true` (matching `.env.example`'s
intent for local dev); or add `env = ENVIRONMENT=local, DEBUG=true` to `pytest.ini` via
`pytest-env`. Prefer the former — it also makes `python -m app.main` work locally.

## 4. What the new tests prove is WORKING

Worth recording, because much of it was previously assumed rather than asserted:

- **The money path runs end to end.** F139 is genuinely fixed. A mid-period rate change
  prices each day at its own rate (₹2,750 for 100@12.50 + 100@15.00), the payslip
  breakdown reconciles `pieces × rate == amount` using H11's blended rate, and every
  employee gets exactly one line.
- **A leaver is paid for pieces but not a salary** — the H13 asymmetry is correct and
  now asserted in both directions.
- **A failed recompute restores the lines it deleted** (B6), and a failed compute
  deletes its own orphan run so the window can be retried.
- **Stock arithmetic is right in every case except the negative floor**: one decrement
  per batch, rework consumes nothing, a double-scanned barcode is charged once, a mixed
  cut/non-cut batch is refused, and a lining cut never touches leather stock.
- **The full nine-stage garment lifecycle works**, including `PACKAGE_EXPORT` and the
  drawer recycling to `WAITING` with both sides of the piece↔drawer link cleared (F11).
- **Barcode history is genuinely sacred**: reissue and deactivate both preserve
  production events and closed wage lines; retired codes 410 for every type (F18);
  cross-type scans (piece code at the employee door) 404 rather than mis-resolving.
- **Mass assignment is closed** — caller-supplied `id`/`is_active` on employee and
  client create are dropped at the boundary; no error body in the suite leaks a
  traceback, a `site-packages` path, or SQL.
